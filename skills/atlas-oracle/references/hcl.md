# Writing Oracle Schemas in HCL

The rules of the HCL schema language that matter on Oracle, and the places where HCL behaves differently
from SQL. The language: https://atlasgo.io/atlas-schema/hcl. Every Oracle block and attribute:
https://atlasgo.io/hcl/oracle. The Oracle driver needs `atlas login`. If `atlas whoami` shows no login,
ask the user to run `atlas login`; a user without an account can start a free trial with it.

## Files and Schemas

- Name Oracle schema files `*.oc.hcl`, test files `*.test.hcl`, and rule files `*.rule.hcl`. The Atlas
  editor plugins recognize `.oc.hcl` for Oracle
  (https://atlasgo.io/atlas-schema/hcl#file-naming-for-editor-support).
- A `schema` block is an Oracle user. At schema scope, its name must be the user in the URL, in
  uppercase, or Atlas fails with `mismatched HCL and database schemas: "APP" <> "app"`. A file with
  several `schema` blocks needs database scope (`references/dev-database.md`).
- When environments use different owners, such as `APP_DEV` and `APP_PROD`, set the name from an input
  variable (https://atlasgo.io/atlas-schema/input-variables):

  ```hcl
  variable "schema_name" {
    type = string
  }

  schema "app" {
    name = var.schema_name
  }

  table "ORDERS" {
    schema = schema.app
    # ...
  }
  ```

  Pass it with `--var schema_name=APP_DEV`.
- `atlas schema test` creates the schema on the dev database, whose schema is `PDBADMIN`, so an HCL
  schema named after the target user fails with
  `mismatched schema names: "PDBADMIN" != "APP"`. Name the schema from a variable, as above, with the
  target user as the default, and run tests with `--var schema_name=PDBADMIN`. A SQL schema has no
  schema names and needs neither. The `docker` block has no `schema` attribute on Oracle.
- Write every label in uppercase: `table "ORDERS"`, `column "CUSTOMER_ID"`. The label is the name Atlas
  quotes, so `table "orders"` creates a lowercase table that every query must quote
  (`references/objects.md`, Names).

## Columns

- A column without `null` is `NOT NULL`, the opposite of SQL. Write `null = true` for a nullable column.
- Types are written inline: `NUMBER(19)`, `NUMBER(12,2)`, `VARCHAR2(100)`, `CHAR(4)`, `RAW(16)`, `DATE`,
  `CLOB`, `BLOB`, `BINARY_DOUBLE`, `FLOAT(126)`, `BOOLEAN`, and `JSON`. Types with a qualifier take
  `sql("...")`: `sql("VARCHAR2(100 CHAR)")`, `sql("TIMESTAMP(6)")`, `sql("TIMESTAMP(6) WITH TIME ZONE")`.
- Write integers with a precision. `INTEGER` and `NUMBER(*,0)` are planned as plain `NUMBER`, which
  accepts decimals (`references/objects.md`).
- `default` takes a literal (`default = 0`, `default = "active"`, `default = false`) or an expression in
  `sql()`: `default = sql("SYSTIMESTAMP")`, `default = sql("SYS_GUID()")`. A `default` block with
  `on_null` plans `DEFAULT ON NULL`, which also makes the column `NOT NULL`. `INSERT_AND_UPDATE` needs
  23ai:

  ```hcl
    column "CREATED_AT" {
      type = sql("TIMESTAMP(6) WITH TIME ZONE")
      default {
        as      = sql("SYSTIMESTAMP")
        on_null = INSERT_ONLY
      }
    }
  ```

- An `identity` block makes an identity column. Without attributes it is `GENERATED ALWAYS`. Unlike a
  sequence's start, an identity's `start` is planned:

  ```hcl
    column "ID" {
      type = NUMBER(19)
      identity {
        generated = BY_DEFAULT
        on_null   = INSERT_ONLY
        start     = 100
        increment = 10
      }
    }
  ```

  It plans `"ID" NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY (INCREMENT BY 10 START WITH 100)`.
- A virtual column takes its expression in an `as` block. Oracle stores none of its values, and
  `VIRTUAL` is the only `type`:

  ```hcl
    column "TAXED_PRICE" {
      type = NUMBER(12,2)
      null = true
      as {
        expr = "PRICE * 1.17"
        type = VIRTUAL
      }
    }
  ```

  Oracle rewrites the expression, which inspects as `"\"PRICE\"*1.17"`, so plan with a dev database.
- `collate` sets a column's collation, which Oracle allows only with `MAX_STRING_SIZE = EXTENDED`:
  otherwise the plan fails with
  `ORA-43929: Collation cannot be specified if parameter MAX_STRING_SIZE=STANDARD is set.`
- `comment` sets a comment on a table, a column, or a view column.
- There is no `renamed_from` on Oracle. A renamed column or table is planned as a drop and an add,
  which loses its data, and `renamed_from` fails with
  `unknown attribute renamed_from in block of type column`. Write renames by hand
  (`references/migrations.md`, Renames).

## Keys, Constraints, and Indexes

- `primary_key`, `unique`, and `foreign_key` blocks require a name. Name a `check` too:

  ```hcl
    primary_key "ORDERS_PK" {
      columns = [column.ID]
    }
    foreign_key "ORDERS_CUSTOMER_FK" {
      columns     = [column.CUSTOMER_ID]
      ref_columns = [table.CUSTOMERS.column.ID]
      on_delete   = CASCADE
    }
    index "ORDERS_CUSTOMER_IDX" {
      columns = [column.CUSTOMER_ID]
    }
    check "ORDERS_TOTAL_CK" {
      expr = "TOTAL >= 0"
    }
  ```

- `on_delete` takes `NO_ACTION`, `CASCADE`, or `SET_NULL`. There is no `on_update`: Oracle has no such
  action.
- Declare an index for each foreign key, as above. Oracle needs one to avoid locking the child table
  (`references/objects.md`).
- A `check` whose whole expression is `"COL" IS NOT NULL` is left out of plans; set `null = false`
  instead.
- `unique` and `primary_key` take `validated = false` for `NOVALIDATE`, plus `enabled`, `rely`, and
  `deferrable` (`INITIALLY_IMMEDIATE` or `INITIALLY_DEFERRED`). Oracle builds a unique index for the
  constraint, which fails on duplicate rows, so point a `NOVALIDATE` constraint at a non-unique index:

  ```hcl
    index "USERS_EMAIL_IDX" {
      columns = [column.EMAIL]
    }
    unique "USERS_EMAIL_UK" {
      columns   = [column.EMAIL]
      index     = index.USERS_EMAIL_IDX
      validated = false
    }
  ```

  It plans the two statements below, which succeed on a table that has duplicates, after which new
  duplicates fail with `ORA-00001`:

  ```sql
  CREATE INDEX "USERS_EMAIL_IDX" ON "USERS" ("EMAIL")
  ALTER TABLE "USERS" ADD CONSTRAINT "USERS_EMAIL_UK" UNIQUE ("EMAIL") USING INDEX "USERS_EMAIL_IDX" NOVALIDATE
  ```

- An `index` takes `columns`, or `on` blocks with `column` or `expr` and `desc`, plus `unique`,
  `bitmap`, `reversed`, `domain` with `parameters`, and a `physical` block. A function-based index:

  ```hcl
    index "ITEMS_NAME_IDX" {
      on {
        expr = "UPPER(\"NAME\")"
      }
    }
  ```

## Tables

- A `physical` block sets the tablespace and storage options (`pctfree`, `pctused`, `initrans`, and a
  `storage` block). Inspection writes it for a table outside the user's default tablespace, and a dev
  database without that tablespace fails with `ORA-00959: tablespace 'APPDATA' does not exist`: create
  the target's tablespaces in the dev `init` (`references/dev-database.md`).

  ```hcl
  table "LEDGER" {
    schema = schema.APP
    # ...
    physical {
      tablespace = "APPDATA"
    }
  }
  ```

- A `temporary` block makes a global temporary table. `on_commit` takes `DELETE_ROWS` or
  `PRESERVE_ROWS`, and plans `CREATE GLOBAL TEMPORARY TABLE ... ON COMMIT PRESERVE ROWS`.
- Partitioning has no HCL attribute (`references/objects.md`).

## Views, Functions, Procedures, and Triggers

Atlas writes PL/SQL bodies as heredocs, with argument names in uppercase:

```hcl
function "ADD_TAX" {
  schema = schema.APP
  arg "P_AMOUNT" {
    type = NUMBER
  }
  return        = NUMBER
  deterministic = true
  as            = <<-SQL
  BEGIN
    RETURN ROUND(p_amount * 1.17, 2);
  END;
  SQL
}

procedure "CREDIT_ACCOUNT" {
  schema = schema.APP
  arg "P_ID" {
    type = NUMBER
  }
  arg "P_AMOUNT" {
    type = NUMBER
  }
  as = <<-SQL
  BEGIN
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_id;
  END;
  SQL
}
```

- `arg` takes `mode` (`IN`, `OUT`, `INOUT`), `default`, and `nocopy`. PL/SQL argument and return
  types have no size: Atlas plans `type = VARCHAR2(100)` as `VARCHAR2`. Write them unsized, such as
  `NUMBER`, `VARCHAR2`, or `VECTOR`.
- A trigger takes one timing block, `before`, `after`, or `instead_of`, with its events. `when` writes
  `NEW` and `OLD` without colons, and the body in `as` uses `:NEW` and `:OLD`:

  ```hcl
  trigger "ITEMS_PRICE_GUARD" {
    on = table.ITEMS
    before {
      insert = true
      update = true
    }
    for  = ROW
    when = "NEW.PRICE < 0"
    as   = <<-SQL
    BEGIN
      :NEW.PRICE := 0;
    END;
    SQL
  }
  ```

  It plans:

  ```sql
  CREATE TRIGGER "ITEMS_PRICE_GUARD" BEFORE INSERT OR UPDATE ON "ITEMS" FOR EACH ROW WHEN (NEW.PRICE < 0) BEGIN
    :NEW.PRICE := 0;
  END;
  ```
- A view takes `as`, `depends_on`, and its `column` blocks.
- A body that does not compile is left out of the plan without an error (`references/objects.md`). Test
  each routine (`references/testing.md`).
- Packages have no block. Write them in migration files (`references/migrations.md`).

## Sequences

```hcl
sequence "ORDER_SEQ" {
  schema    = schema.APP
  increment = 1
  cache     = 50
}
```

- `start` is not planned: the sequence starts at 1. Set the first value with `START WITH` in a migration
  file, or with a one-time `ALTER SEQUENCE ... RESTART START WITH n` (`references/objects.md`).
- Never use `min_value` as a start: once the sequence is used, later plans restart it at that value.
- `order = true` sets `ORDER`, which keeps numbers in request order across RAC instances. `cycle`,
  `max_value`, and `cache` take Oracle's meanings.

## Seed Data

Rows are declared next to the table in a `data` block, and applied only when the env enables data sync
(https://atlasgo.io/atlas-schema/hcl#preserving-explicit-ids):

```hcl
data {
  table = table.COUNTRIES
  rows = [
    { CODE = "US", NAME = "United States" },
    { CODE = "CA", NAME = "Canada" },
  ]
}
```

- `GENERATED ALWAYS` identity values are skipped, even with `preserve_ids = true`. `BY DEFAULT` and
  `BY DEFAULT ON NULL` values are written when the env's `data` block sets `preserve_ids = true`.

## Input Variables

Input variables work as in any Atlas HCL schema (https://atlasgo.io/atlas-schema/input-variables). A
variable without a default that gets no value fails the run.
